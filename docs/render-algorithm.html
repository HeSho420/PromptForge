PromptForge — How the Render Algorithm Works

The picture book edition. Every diagram below is what actually happens when you press Run edit or Forge — no simplifications that lie.

1The four brains

PromptForge is a conductor. Four local AI engines do the specialist work, and the pipeline's job is to ask each one the right question at the right moment.

2One edit, start to finish

Every Studio edit walks these stages — you can watch them live in the Pipeline stepper. The amber loop is the quality engine: a bad render gets retried, but a retry can never undo your edit (section 4).

3How the mask is chosen

The mask is the safety fence: the painter can only touch white pixels. Three routes, in strict priority order — and the mask is checked by the vision model before any paint is spent.

3bDid the render actually do what you asked?

A render can be beautiful and still ignore half the request. So the request itself is turned into a short list of things that must be true of the picture, and each one is checked separately.

3cIf it missed, change the recipe — not the dice

Re-rolling the seed of a recipe that already missed is a coin flip on the same coin. Every retry now changes something real, cheapest change first, and no combination is ever tried twice.

Stops as soon as it is right. A first render that delivers every requirement ends the job — the ladder costs a full render per rung and is never spent on a picture that already obeys. And a request for something deliberately un-photoreal (“a flat cartoon drawing”) counts as satisfied: a low realism score is the correct answer there, not a reason to try again.

4The quality loop — and the rule that protects your edit

Alongside the request check, the vision model fills a six-part scorecard. Below the target? The final step re-renders (new seed, sharpened prompt, and from round two a different model or technique). But here is the part that makes retries safe:

realismdoes it look like a photo, not AI soup?
prompt accuracydid it actually do what you asked?
identity preservationis everything you did NOT ask about untouched?
scene consistencylighting/perspective still coherent?
artifact-freeno seams, smears, extra fingers…
visual qualitysharpness, color, overall polish
The problem it solves: a retry that quietly undoes your edit scores great on realism and consistency — the old average-based compare would pick it. You saw this live: "the pipeline undid the changes I asked for."
The keep-best gate: a retry may replace the current best only if prompt-accuracy does not drop more than 5 points. A big accuracy gain (+10) wins even if the average slips a little; otherwise the higher average wins. In the logs: a retry is never allowed to undo the edit.

5Outpainting without the tell-tale seam

Outpainting = inpainting the new margins. Three rules keep it invisible — each one exists because its absence produced a real bug (hard seams, extra people, warping).

soft blend, not hard cutmodern soft-inpaint conditioning (DifferentialDiffusion) replaced the legacy encode that produced the visible boundary.
best inpaint modelthe highest-ranked installed inpaint checkpoint does the blending — not the 2022-era default.
anti-duplicate negative"extra person, duplicated subject, cloned face, split image…" is always in the negative prompt.

6Forge: text → image from scratch

Generating is different from editing: there is no mask and no original to protect. Instead, the LLM writes the render program (a ComfyUI graph) and the pipeline refuses to run anything it can't verify.

7The safety nets

Everything above assumes things go wrong — because on real hardware they do. Each net catches a specific, real failure we have seen:

ComfyUI crashed?auto-restarted from disk, render resumes — a health monitor probes it every 15 s.
Ollama down?restarted before any planning or judging call.
LLM wrote a bad graph?the real error goes back to the LLM for a repair round — with the machine's actual node list.
Wrong mask?one corrective re-segmentation, kept only if the vision check now passes.
Model missing or gated?auto-download with checksum, and a public-mirror hunt when the official file is gated.
Out of memory?canvas/steps clamped to the hardware budget up front; video renders check free memory before the multi-minute load.
Better model exists?the pipeline stages a modern inpaint model download in the background — the next edit uses it.
Lessons rememberedevery failure diagnosis and proven fix lands in a knowledge base the planner reads next time.
